# 测试分类与用途标注：三级功能分类 v2

日期：2026-10-10。按本轮确定的结构整理，替代 v1 的通用/专项主分类。

**一级：产品功能 → 二级：测试意图 → 三级：测试材料类型。**

一级固定为：**双引擎代码审计、代码修复、规则生成**。每次测试沿这三个层级归类，再关联具体材料、任务、项目改进版本和执行批次。同一来源可服务不同功能，其材料 ID 保持一致。

依据：[材料登记](../manifests/current-test-inventory.json)、[上一版本地盘点](classification-draft-v1.md)、[10-09补测](../../docs/research/supplemental-20261009-results.md)、[产品链路记录](../../docs/research/chain-completion-20261009-results.md)。当前共32项来源/候选登记，包含尚未形成可运行任务的参考项；另有自建测试资产。已有结果的逐项用途及改进版本见[已收集测试结果分类表](collected-results-classification.md)。

## 分类层级和使用方式

| 层级 | 回答的问题 | 示例 |
| --- | --- | --- |
| 一级：功能 | 测试哪个产品功能？ | 双引擎代码审计 |
| 二级：意图 | 想验证这个功能的什么表现？ | 代码审计准确性 |
| 三级：材料类型 | 用什么类型的输入开展测试？ | 项目测试、专项测试集测试 |
| 具体任务 | 实际测试哪个项目/哪些样例？ | RealVuln的Flask/DVNA；OWASP冻结子集 |

三级类型按实际任务输入和评分单位判定：

| 类型 | 定义 | 典型材料 |
| --- | --- | --- |
| 项目测试 | 以完整项目或固定项目快照开展检查；按实际根因、调用链、业务合同与项目回归裁决 | RealVuln两项目、六个自然JS配对项目、两语言HTTP夹具 |
| 专项测试集测试 | 针对明确CWE、告警复核、修复或QL任务，使用固定样例/模块/标签和评价规则 | OWASP样例、SastBench告警任务、10模块修复任务、六族QL正反例 |
| 工程流程用例测试 | 检查接口、队列、隔离、恢复、人工门、浏览器、下载与发布流程 | pytest契约、CodeQL/Docker集成、GUI/Worker流程夹具 |

一个数据集即使来自真实仓库，若本次只测其中的函数/告警/特定任务，仍归“专项测试集测试”；项目级任务则归“项目测试”。性能和可靠性是二级意图，不能把“性能测试”与“项目测试”并列作为同一层级。

就绪、暴露、语言与对照方式是附加标注：可回归/源码候选/待补齐/仅参考，开发/回归/待准入，支持语言，基线对照/竞品同任务/消融。原A/B协议可作为对照方式参考，功能分类以本文为准。

## 一、双引擎代码审计

范围：CodeQL静态分支、独立Scout分支、合流及统一复核。静态、Scout、原始并集、最终复核分别报告，避免将最终准确性归因给某一路。

| 二级：测试意图 | 三级：材料类型 | 具体项目/测试集 | 用途、指标与当前状态 |
| --- | --- | --- | --- |
| 1.1 审计准确性 | 项目测试 | RealVuln Flask/DVNA；六个自然JS配对；后续OpenSSF项目 | 目标根因TP/FP/FN、精确率/召回率、源码支持。RealVuln已开发暴露；JS按任务裁决；OpenSSF需补源码。 |
| 1.1 审计准确性 | 专项测试集测试 | OWASP固定子集；自建Py/JS注入及业务条件正反例 | 同输入比较静态/Scout/并集/复核；按冻结CWE及样例单位计分，已评分部分用于回归。 |
| 1.2 业务语义、跨文件取证与定位 | 项目测试 | Flask/DVNA、自然JS；BAC-Bench与VulnGym目标项目候选 | 对象所有权、跨租户、状态和调用链；证据完整性、根因定位与未知前提。BAC/VulnGym仍需补固定目标源码/任务。 |
| 1.2 业务语义、跨文件取证与定位 | 专项测试集测试 | ownership/tenant/state六样例；VLoc、CrossCommit候选 | 单独检查业务条件或定位；历史/跨提交任务先核对产品支持范围和oracle。 |
| 1.3 告警复核与误报控制 | 项目测试 | 实际项目中的CodeQL/Scout告警及反证 | 源码支持、排除理由、弃权、漏删真阳性；整套告警审查与目标CWE计分分开。 |
| 1.3 告警复核与误报控制 | 专项测试集测试 | SastBench、AACR-Bench；VEX-Bench候选 | 告警/评论正确性、证据不足与供应链可达性。前两者已有标签、缺完整上下文；VEX未形成本地可测集。 |
| 1.4 检查覆盖与失败处理 | 项目测试 | DVNA模板/配置、项目窗口和任务矩阵 | 实际读取范围、未检查窗口、unknown任务、失败分支；不能把窗口完成当作安全判定完成。 |
| 1.4 检查覆盖与失败处理 | 工程流程用例测试 | 双分支汇合、分页/预算、扫描失败、任务与证据隔离用例 | 分支失败不伪装为空告警成功，未评估不默认排除；检查恢复和结果保存。 |
| 1.5 耗时、成本与模型/引擎贡献 | 项目测试或专项测试集测试 | 对上述同一冻结任务做静态/Scout/复核对照 | 分段耗时、真实调用/token、覆盖；固定输入/预算，注明缓存、并发和复用。用途独立于准确性统计。 |
| 1.6 审计产品链路 | 工程流程用例测试 | 两语言真实上传→Worker→发现/复核、源码/SARIF导出、GUI | 验证真实流程及页面状态；最新链路仍部分执行，不能标全链路通过。 |

建议实例：**双引擎代码审计 → 审计准确性 → 项目测试 → RealVuln/Flask**；**双引擎代码审计 → 审计准确性 → 专项测试集测试 → OWASP/validation-01**。

## 三、规则生成

范围：需求/源码准备、双库检索、QL生成、编译/开发反馈、独立验收、发布和再用。漏洞检测规则与复审锚点按用途分开；旧规则执行和新模型生成分开。

| 二级：测试意图 | 三级：材料类型 | 具体项目/测试集 | 用途、指标与当前状态 |
| --- | --- | --- | --- |
| 3.1 生成成功率与可执行性 | 专项测试集测试 | 六族QL任务、CQLLM Python任务候选 | 新生成请求→编译→开发执行→验收的端到端成功率与失败；CQLLM需先转换任务、隔离作者答案。 |
| 3.1 生成成功率与可执行性 | 项目测试 | 真实项目未建模来源/目标根因，外部API source样例 | 固定项目和实际API事实生成查询，记录可执行性及原项目目标命中；派生例与自然项目分别标注。 |
| 3.2 规则检测准确性与安全反例 | 专项测试集测试 | 六族隐藏正反例、12新探针文件、独立QL holdout候选 | TP/FP/FN、隐藏检测和未执行。12文件针对历史18候选的迁移，不能计入新生成成功率。 |
| 3.2 规则检测准确性与安全反例 | 项目测试 | 漏洞前后自然JS项目、派生后的真实项目任务 | 对固定目标根因及安全变体执行；上游后快照不自动作为全项目安全负例。 |
| 3.3 新增覆盖与跨项目/框架迁移 | 项目测试 | 六个JS项目、OpenSSF候选、外部API source扩展 | 标准规则复用/模型扩充/新检测器分别标识，检查基线漏检与新增覆盖。 |
| 3.3 新增覆盖与跨项目/框架迁移 | 专项测试集测试 | helper、POST body/form、别名、SQL格式化、净化/遮蔽探针 | 验证更复杂数据流与安全反例；同规则/同族重复轮次不算独立新增漏洞。 |
| 3.4 RAG与执行反馈的贡献 | 专项测试集测试 | 同任务旧K/自由QL/规格、BM25/向量/融合、反馈/无反馈对照 | 固定源码、模型、语料和预算，比较独立效果；已有工程可用性不能替代因果消融。 |
| 3.5 检索与资料约束正确性 | 工程流程用例测试 | reference/rule_example查询、资料槽、版本/引用与隔离用例 | 检索匹配、资料可用性、真实引用、版本冻结；官方RAG范例不兼任隐藏金标。 |
| 3.6 编译/开发循环与缓存可靠性 | 工程流程用例测试 | 动态查询缓存、不同QL同库执行、候选失败与恢复用例 | 查询内容和结果真实绑定、失败保存、恢复去重、正反例状态，旧缓存作废结果保留诊断。 |
| 3.7 批准、发布与规则再用 | 工程流程用例测试 | 两语言生成→人工批准→holdout→发布→新上传再用 | 明确阶段门、发布版本冻结、停用和导出；本轮浏览器真实发布链尚未评估。 |
| 3.8 耗时与成本 | 同任务项目测试或专项测试集测试 | 上述固定生成任务 | 分别记录检索/embedding、生成、编译、执行和验收；成功/失败请求均入成本分母。 |

建议实例：**规则生成 → 规则检测准确性与安全反例 → 专项测试集测试 → 12新规则探针**。
