# 图七 规则验收与新样本迁移结果

放置位置：3.4.3、3.4.4 或3.4.6。图类型：分阶段计数图与迁移结果矩阵。

数据来源：docs/research/rag-stabilization-results.md，以及docs/research/supplemental-20261009-summary.json的rules。

## 文本内容

图题：规则可执行性检查与独立样本验收的区别。

本图并列展示两个不同批次，不能将两批结果合成一次新的生成实验。第一部分来自2026-10-04的full_v8历史规则生成实验：Python和JavaScript的eval、SQL、反射XSS六类任务，各运行三轮，共18个生成请求。编译通过18/18、开发执行通过18/18、端到端独立验收通过15/18。编译及开发执行全部通过，但独立验收仍存在失败，说明可执行性不能替代独立质量检验。

第二部分来自2026-10-09补测：冻结上述18个历史候选，在新的控制／数据流正反例上执行迁移检查，没有新规则生成请求。六个任务家族各有3个历史候选，结果为：JavaScript eval 3/3，JavaScript SQL 3/3，JavaScript XSS 3/3，Python eval 3/3，Python SQL 3/3，Python XSS 0/3。合计15/18通过、3/18失败、0执行错误。Python XSS候选遗漏新包装返回中的正例，其他五类在本批探针上通过。

每个家族的3列表示历史重复轮次的候选，不代表3个独立漏洞。第二部分使用12个新源文件，包含12个正例sink和12个安全处理分支。测试对象为历史漏洞检测器用途，不是当前默认复审锚点的新生成结果。两部分不能证明RAG相对无RAG的因果增益，也不能推出任意语言或CWE的总体可用率。

## 绘图意图描述

绘制明确分隔的双面板学术结果图。(a)标题“历史生成验收｜2026-10-04”，三根水平条分别表示“编译18/18”“开发执行18/18”“独立验收15/18”，坐标为请求数0—18，直接标数值和分母；在独立验收条右侧加小注“可执行不等于独立验收通过”。(b)标题“冻结旧候选的新样本迁移｜2026-10-09”，绘制6行3列矩阵，六行按JS eval、JS SQL、JS XSS、Python eval、Python SQL、Python XSS排列；列为“历史轮次1、2、3”。前五行全部为青绿色格，内写“通过”；最后一行全部为淡橙红色格，内写“失败”，行末标0/3，另加“包装返回正例遗漏”。矩阵下方写“合计15/18；执行错误0；新生成请求0”。两个面板之间不用延续箭头或漏斗，明确是不同批次。底部注记“六任务家族×三历史轮次；派生小样本；不代表RAG因果收益或复审锚点新生成成绩”。不使用总体100%可用标章，不混入旧报告53条规则的统计，不添加显著性标记。
