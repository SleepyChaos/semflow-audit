## 4. 当前审计流程

### 4.1 发现：CodeQL 与 AI 粗筛并行

新任务以同一不可变源码快照启动 CodeQL 扫描和独立 Scout，两条分支完成后汇合。

CodeQL 提供静态告警及位置、规则和数据流等信息。Scout 独立阅读项目源码窗口，不以 CodeQL 告警为输入，因此可以提出静态告警之外的候选。

Scout 采用项目地图、轮转窗口和有限步取证，输出必须能绑定真实源码位置与引用。当前不是固定抽样三条 Source/Sink 路径，也没有实现完整运行时调用图。

覆盖范围、未检查部分及分支失败会保留。CodeQL 失败不代表无漏洞；若 Scout 留下足够可审查材料，系统允许在部分失败状态下继续复审。

依据：[dual_scanning.py](/Users/chaos/Documents/GitHub/semflow-audit/backend/app/services/dual_scanning.py)、[scouting.py](/Users/chaos/Documents/GitHub/semflow-audit/backend/app/services/scouting.py)、[scout.v7.txt](/Users/chaos/Documents/GitHub/semflow-audit/backend/app/prompts/scout.v7.txt)、[test_dual_discovery.py](/Users/chaos/Documents/GitHub/semflow-audit/tests/test_dual_discovery.py)。

## 5. 修复能力与边界

Repair 2 先形成项目理解、目标流程和允许修改范围，关键事实需要源码证据；重要语义未知或矛盾时阻断。

每次候选在独立工作副本中应用精确替换并生成 Diff，最多尝试三个完整候选，失败反馈用于后续尝试。原始源码快照保持不变。

验证按用户选择执行。默认检查包括语法；可选择 Python pytest 或 JavaScript 测试模式，并配置 CodeQL 复扫。执行受容器资源、网络、权限和时间限制约束。

“检查通过”只能表示所选验证项通过。不能据此保证所有业务逻辑、接口兼容和行为语义保持一致；TS/JSX 等未受支持的语法验证也不能伪装成功。

候选仍需人工接受，接受前再次检查相关身份、证据及完整性条件；用户可以下载 Diff，系统不直接改写原始上传快照。

## 6. 规则生成、检索与发布

当前输入区分复审锚点、漏洞检测器、框架模型三种用途，默认用途为复审锚点。不能把每条生成规则都称为独立漏洞检测器。

检索使用参考资料与规则示例两类语料，保留来源、版本与摘要，并按语言及 CodeQL 依赖匹配。当前没有独立 reranker，也没有 ChromaDB。

向量与混合模式依赖真实可用且身份一致的嵌入索引；缺失时不能虚报已使用向量检索。

规则链路为：检索与准备 → 生成 → 编译 → 开发正反例 → 项目回放 → 保存草稿 → 人工批准样本 → 样本及独立验收 → 显式发布 → 后续任务选择已发布版本。

生成阶段最多两个完整候选；接口层的格式重试与完整候选次数是不同口径。原稿“最多三轮编译修正后自动入库”不适用当前实现。

存在结构化约束的部分漏洞族与自由 QL 生成路径，两者验证覆盖不同，不能泛化为所有 CWE 或框架均已稳定支持。

若选择项目目标，还需要检查位置、类型及人工根因确认。没有目标时项目增量效果属于未评估，不能视为已验证新增检出。

发布受到样本审批、独立验收、依赖版本与产物完整性等条件约束。未来审计任务显式选择规则版本，并冻结该选择。

依据：[RuleRequest](/Users/chaos/Documents/GitHub/semflow-audit/backend/app/contracts/stages.py)、[RulePanel.tsx](/Users/chaos/Documents/GitHub/semflow-audit/frontend/src/features/rules/RulePanel.tsx)、[规则工作流](/Users/chaos/Documents/GitHub/semflow-audit/backend/app/workflows/rules.py)、[rule_synthesis.py](/Users/chaos/Documents/GitHub/semflow-audit/backend/app/services/rule_synthesis.py)、[rule_development.py](/Users/chaos/Documents/GitHub/semflow-audit/backend/app/services/rule_development.py)、[rule_holdouts.py](/Users/chaos/Documents/GitHub/semflow-audit/backend/app/services/rule_holdouts.py)、[rules.py](/Users/chaos/Documents/GitHub/semflow-audit/backend/app/services/rules.py)。
