# 当前测试数据的缺口与补充顺序

日期：2026-10-09。用于省赛报告准备；只复核现有记录，本轮未新增模型调用或执行实验。

## 总体判断

当前有代码可靠性测试、微样例、开发项目、规则稳定化对照及 OWASP48 验收。最需要补的是独立任务、可信判定标准、同条件对照和实际产品验收。登记了 32 项材料候选，不等于 32 个已可运行数据集；不少材料只有索引、片段或缺少目标依赖。

优先程度：P0 是支持参赛核心能力声明的必要缺口；P1 用于扩大结论范围。下述样本数是控制工作量的起步建议，不是统计充分性保证，不能仅因达到数量就宣称显著或全面领先。

## 1. 漏洞发现：缺新盲测、JS 和陌生框架【P0】

现状：已有 OWASP Python 56 例探索、后续两个开发批与一个 48 例预留验收，以及 RealVuln Flask/DVNA 开发回归。全量 1230 例主要完成静态工具扫描，AI 全量未跑。当前 48 例验收标签已经暴露，后续复用只能作为回归，不能当新盲测。每类只有少量正负例，不能据类内满分证明稳定能力。

补充：

- 冻结新种子至少 3 批各 48 例作为可负担的同分布复测起点；排除此前暴露文件，并按模板/结构分组，而不只检查文件名不同。
- 准备 10–20 个跨仓库独立任务，尽量平衡 Python/JavaScript，覆盖至少数个不同框架；按仓库和根因拆开发/隐藏组。
- 重点含跨文件传播、辅助函数、动态入口、对象归属授权、认证与授权区分、编码/净化、常量覆盖、路由输入约束、可变容器状态。
- 增加安全近似反例及少漏洞/无已知目标的正常项目，减少只用 1:1 正负样本造成的精确率失真。

指标：TP/FP/FN/TN、P/R/F1/FPR，按语言/框架/CWE 分层；独立根因级新增真漏洞、重复报告及弃权/未完成率。新同分布批与真实仓库分别报告。

来源：[OWASP48 结果](/Users/chaos/Documents/GitHub/semflow-audit/benchmark-data/experiments/owasp48-final-comparison.md)、[当前材料清单](/Users/chaos/Documents/GitHub/semflow-audit/benchmark-data/test-programs/inventory.md)。

## 2. 告警真值：缺统一人工盲审【P0】

现状：OWASP48 主分数是“精确文件＋目标 CWE 案例命中”，不是所有报告的逐条准确率。平台有 34 条目标标签外告警未逐条裁决；supported 不是人工金标，真实项目的标签也未必完整。

补充：冻结所有工具的输出，隐藏系统名/模型名，由至少两名审阅者独立判断实际操作、输入或业务政策、保护条件、根因及证据；有分歧保留理由并裁决。若暂不能全量审阅，预先定义分层抽样与权重，报告抽样范围，不能只挑新增或看起来正确的告警。

分别计量“发现了目标但 CWE 分类不一致”“真正误报”“重复根因”“证据不足”和“静态源码条件成立但部署可利用性未知”。未匹配官方标签不自动算 FP；CWE 匹配规则提前冻结，不能看结果后换映射。

来源：[现有计分与未裁决范围](/Users/chaos/Documents/GitHub/semflow-audit/benchmark-data/experiments/owasp48-final-comparison.md:11)。

## 3. 辅助修复：缺正式联合安全/功能任务，存在已观察回退【最高优先级 P0】

现状：早期两个简单业务案例新旧均 6/6；后续同一真实 JS 模块三轮，旧版 3/3、新版 1/3，主要涉及上下文/预算失败。现有四模块 oracle 校准只得到一个有界候选，仍待人工复核，正式可评分自然漏洞任务为 0。官方补丁或人工补丁通过不能计为模型修复率。

补充：

- 先从 10–20 个完整 Python/JS 快照候选中建立至少 20 个独立修复任务的目标池；正式分母只采用预先通过准入的任务，候选不足则报告实际数量。
- 每项有正常业务与目标安全两套独立判定测试：原版正常行为通过、安全断言失败；参考修复正常/安全均通过。检查参考补丁是否不完整或主动删除 API，不能无条件把 post 当安全真值。
- 包含“封死所有输入”“移除正常 API”“只修一种绕过”“目标告警消失但仍有同根因问题”等负面补丁；功能覆盖权限矩阵、返回值/异常、跨模块副作用和边界输入。
- 同任务、同预算比较旧版、直接修复、语义上下文及反馈机制；保存模型流程失败与事后补丁检查两套结果，不用事后通过覆盖首次失败。
- 已知漏洞修复和实际审计驱动的端到端修复分开计分，后者包含漏报、错误目标和未确认目标。

先沿用当前不启动目标服务的范围，校准纯单元可验证任务；需要浏览器/服务/利用重放的任务单列未执行，不能用 mock 代替真实语义背书。

指标：生成完成率、补丁可应用率、功能保持率、安全断言通过率、联合通过率、未评估与环境失败。语法通过与 CodeQL 复扫不能单独证明“根源修复”或无新漏洞。

来源：[修复校准](/Users/chaos/Documents/GitHub/semflow-audit/benchmark-data/experiments/repair-calibration-report.md:24)、[后续真实模型比较](/Users/chaos/Documents/GitHub/semflow-audit/benchmark-data/experiments/calibration-results.md:81)、[早期业务案例](/Users/chaos/Documents/GitHub/semflow-audit/docs/research/semantic-development-results.md:82)。

## 4. 规则生成：缺独立多项目隐藏正反例【P0】

现状：v8 的 18 请求是六类需求各三次，不能视为 18 个独立漏洞。编译 18/18、端到端 15/18 只支持这组任务稳定性；后续两项 OWASP 派生任务未证明目标检出收益，且评测入口/参考查询还需校准。默认复审锚点、官方模板复用与新增检测器需要分开。

补充：冻结至少 20 个独立 Py/JS 规则需求；每项先用参考 QL 证明在固定入口、版本和依赖下可解，再留出至少 3 个漏洞变体与 3 个安全反例作为起点。包含导入别名、同名普通函数、可信常量、净化、wrapper、跨文件及另一个仓库迁移。

按项目、API 与漏洞根因隔离开发和隐藏集；去重 RAG 范例及作者已有输出，隐藏修复 diff、查询与测试不能回流生成器。常规能力内与实验性自由 QL 分开，不能为了扩大覆盖统计忽略产品支持范围。

指标：编译、开发执行、目标根因匹配、隐藏正例召回/负例误报、跨项目迁移、正式发布；单列相对固定 CodeQL 真正新增且经确认的覆盖。

来源：[规则稳定化结果](/Users/chaos/Documents/GitHub/semflow-audit/docs/research/rag-stabilization-results.md:56)、[后续校准](/Users/chaos/Documents/GitHub/semflow-audit/benchmark-data/experiments/calibration-results.md:96)。

## 5. RAG：缺独立相关性标签和可隔离的因果对照【P0/P1】

现状：完整方案、BM25 与旧最佳在现有小集同为 15/18，没有向量独立增益证据。查询全部返回或 CWE 元数据相同不等于内容相关、版本正确或查询可用；扩大语料数量也不等于提升质量。

补充：构造 30–50 个独立知识需求，由人工标注资料/API 版本/范例适配性，包含版本冲突、相似漏洞、缺资料及用户不可信文档。分开评估检索和最终规则。

使用相同生成模板、类型化约束、反馈、模型及预算比较无检索、BM25、向量、混合；当前契约限制下 NoRAG 尚未完整支持，先设计明确的研究控制协议，不注入假知识 ID 绕过验证。测资料库/范例库的作用时一次只改变一个因素。

指标：Recall@k、MRR/nDCG、版本错误率、上下文重复率；最终隐藏验收率及 token/调用开销。没有效果提升时如实报告相当或退化。

来源：[现有 RAG 对照](/Users/chaos/Documents/GitHub/semflow-audit/docs/research/rag-stabilization-results.md:88)、[无检索与代理指标限制](/Users/chaos/Documents/GitHub/semflow-audit/benchmark-data/experiments/calibration-results.md:96)。

## 6. 公平基线、速度与可靠性【P0/P1】

现状：CodeQL、Bandit、阿里 OCR 有同 OWASP48 实跑，但输入能力、工具预算与报告格式未完全对齐；只有单轮阶段时间，非产品 GUI 端到端并发耗时，尚缺稳定延迟和费用证据。此前也出现真实工具 OOM、解析失败。

补充：固定当前 CodeQL 套件，扩展套件另列；增加同模型、同源码工具权限与相同预算的普通 Agent/直接 LLM 控制组。规则/修复各自设置同任务基线，不能拿论文异语言数据直接排名。

速度样本按项目大小/文件数/候选数分层，小、中、大项目各取若干独立快照，固定并发与缓存条件重复测量。保存从上传到报告完成的实际墙钟、各阶段、恢复/重试、检索/embedding 与模型成本收据；少量运行优先报全部观测，不用不足样本包装稳定 p95。扩大轮数后再给分位数及区间。

加入队列中断、模型超时、无效 SARIF、CodeQL OOM、预算耗尽、恢复、并发用户和产物损坏等场景。现有可靠性测试作为基础，补实际组件链路的失败证据；失败不能算零漏洞或从质量/完成率分母删除。

来源：[时间与对照限制](/Users/chaos/Documents/GitHub/semflow-audit/benchmark-data/experiments/owasp48-final-comparison.md)、[真实失败记录](/Users/chaos/Documents/GitHub/semflow-audit/benchmark-data/experiments/calibration-results.md:44)。

## 7. 产品验收：缺审计功能 GUI 证据【P0】

现有 CLI/API、真实工具集成和前端构建不能代替审计界面验收；现有专门 GUI 清单尚未执行。通用登录/用户等前端测试也不能证明四阶段流程可操作。

补充：用当前真实页面完成上传→发现→证据复审→人工决定→修复 Diff 与接受→规则审批/独立验证/发布→新上传选择规则→报告导出。至少有一次完整成功链路、一次明确失败/未决链路及两个账号的隔离检查；记录版本、audit/stage ID、实际状态、截图与执行日期。

只验收实际实现的功能，不沿用旧报告中的七语言、季度 PDF 或 CWE 批量删除。真实模型与测试替身分开标注；对展示证据、按钮状态和最终 API 状态作一致性核对。

来源：[GUI 清单](/Users/chaos/Documents/GitHub/semflow-audit/docs/semantic-development-checklist.md)。

## 8. 每项任务必备的数据包与建议顺序

统一记录 task ID、仓库/许可证、完整 commit 与快照 hash、语言/框架版本、CVE/根因与正常合同、证据和判定测试、人工审核状态、开发/隐藏划分与暴露情况。运行记录关联代码/Prompt/模型/CodeQL/语料版本、预算、所有重试、完整输出、失败及用量。不同年代、不同协议结果分别成表，不累计最好轮次。

建议顺序：

1. 先清点任务准入与人工盲审，建立新的隐藏集；修复先校准双判定测试，规则先确认参考 QL 可解。
2. 跑确定性基线，再执行同预算模型对照；预算不足时先完成少量但完整的跨项目任务，分别报告，不凑样本数。
3. 完成审计 GUI 验收和当前冻结版本复测，再生成参赛测试表。
4. 追加更大规模、独立框架、语言迁移、消融与性能分层，按仓库/根因组给置信区间。重复三轮用于稳定性，不能当作三份独立任务。

详细设计沿用并补全 [正式评测协议](/Users/chaos/Documents/GitHub/semflow-audit/benchmark-data/evaluation-protocol.md)，无需为报告另造一套宽松计分规则。
