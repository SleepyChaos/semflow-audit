# 多语言项目审计改造待办

创建日期：2026-10-12。状态：待规划与实现。

## 问题与目标

综合项目可能同时包含 Python 后端、JavaScript/TypeScript 前端及其他语言。当前平台一次审计任务只选择一种语言，该选择影响 CodeQL 扫描、AI 粗筛、修复验证和 RAG 规则生成。

当前源码快照保留其他语言文件，但保留文件不代表已经审计。单语言扫描完成不能表示整个项目审计完成；分别扫描两种语言也不能直接证明跨语言业务链路已被检查。

目标流程：上传完整项目 → 自动识别语言 → 确认审计范围 → 按语言执行 → 汇总项目报告 → 复核跨语言接口与业务边界。默认覆盖全部支持语言，手动选择保留为高级选项。

实现以 `design/` 中的功能和模块边界为依据，源码位于 `system/`，评测位于 `benchmarks/`。本文件仅记录待办，不表示相关能力已经实现。

## 待办清单

- [ ] 区分业务源码、第三方依赖、生成文件与资源文件，公开识别和排除依据。
- [ ] 上传页面默认选择全部支持语言，允许用户调整范围。
- [ ] 明确展示不支持的语言和未选择的范围，避免将其记为安全或已审计。

### 任务与扫描编排

- [ ] 保留一个项目级审计入口与不可变源码快照，按语言创建独立子任务。
- [ ] 各语言使用匹配的 CodeQL 抽取器、固定查询包及 AI 检查范围。
- [ ] 子任务通过持久化 ID 和产物引用关联，保留语言、配置、证据与执行历史。
- [ ] 设计并发、重试、取消及资源预算；同时约束单语言预算和项目总预算。
- [ ] 分别记录成功、失败、部分覆盖与未评估，单个语言失败不得隐藏在项目成功状态中。

### 统一复核与跨语言业务边界

- [ ] 汇总各语言的告警和候选，保留原始来源、位置与触发路径。
- [ ] 识别前后端接口、请求参数、鉴权约束及服务间通信等关联线索。
- [ ] 在实际证据支持下复核跨语言业务关系，明确未知前提与未覆盖边界。
- [ ] 将接口关联线索与已证实的数据流区分，不能把接口名称匹配当作完整跨语言调用链。
- [ ] 根因合并需要证据与人工确认，避免同一问题重复统计或错误合并。

### 修复、规则与报告

- [ ] 按修改文件的语言和项目依赖选择验证环境；涉及多语言的补丁需要分别验证。
- [ ] 对跨语言修复保留接口契约、正常行为和安全边界的验收测试。
- [ ] RAG 检索和规则生成明确目标语言与固定语言库版本，避免资料混用。
- [ ] 项目报告展示各语言状态、审计范围、覆盖限制及整体完成依据。
- [ ] 区分“引擎执行结束”“所选范围完成”和“整个项目已审计”，不作超出证据的结论。

## 验收要求

- [ ] 同一 Python＋JS/TS 项目能够上传一次，并生成可独立追踪的语言子任务。
- [ ] 某语言扫描失败时，另一语言的结果仍可查看，项目报告明确失败范围。
- [ ] 未支持、未选择和未评估的源码不会被标为已审计或默认排除。
- [ ] 重试保留原执行历史，任务间证据和产物不会混用。
- [ ] 使用接口关联的正反例验证跨语言复核，不仅检查字段或函数是否存在。
- [ ] 多语言补丁只有在所需验证通过后才能确认修复；未执行的验证不得算通过。

## 当前临时使用方式

混合语言项目可使用同一个 ZIP 分别创建 Python 和 JavaScript/TypeScript 审计任务。该方式提供分语言检查，跨语言接口和业务边界仍需单独复核。
