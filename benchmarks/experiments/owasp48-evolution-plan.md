# OWASP48循环演进与横向比较计划

2026-10-07。用户授权按48例抽样开展测试、通用改进、再测试。

## 冻结设计

- 固定OWASP BenchmarkPython提交和既有去答案输入导出；每批48例，24正24负，全部14类，每类至少一正一负。抽样种子2026100748。此前56例排除。
- 预留development-01、development-02、acceptance-01三批144例，文件互不重叠；验收批不参与调试。按AST结构变换审计近重复，报告跨批结构暴露；公开合成材料、训练暴露未知，只称OWASP同分布评估。
- 分类口径继续精确文件+CWE，不按结果事后调整类别。原始输出、字段恢复、真正新增发现分别说明。outside告警另列，不当作OWASP标签内误报或真阳性。
- 模型、温度、引擎/pack/suite、源码、提示/实现hash、预算固定。每4例一组，共12组，并发3。每Scout/Review阶段上限28调用、50万token、600秒，所有恢复计入。每轮独立完整运行，不按漏报列表补跑。
- 当前版冻结为可执行base；最多两个一般性生产修订，最多6次平台48例运行。候选测试顺序：base/dev01→改进/dev01→改进/dev02→必要时第二修订/dev02→base/acceptance→最终/acceptance。开发批重跑用于诊断，验收不参与后续调整。
- 校验标签不进入模型、工具根目录或RAG。静态扫描实际在同一48例源码快照运行并计时；平台CodeQL与Agent独立后合流复审，研究串行调度墙钟不能冒充GUI并发总流水线速度。

## 改进与停止要求

先读取每阶段日志、实际证据、候选裁决和失败类别，再修机制：权限政策不可凭公开route名称猜测；实际响应/编码、传播路径、保护反证以源码和有版本来源的框架事实为准；工程失败不应扩散到独立候选。不能增加特定case/仓库/CWE答案分支。

目标是相对CodeQL提升F1/召回同时精度不下降，相对Agent粗筛减少误报；相对真实LLM竞品记录精度、召回和实际成本/墙钟的取舍。如果未达到或效果退化，报告平台期和局限，不承诺总榜领先。6次上限内完成独立验收即停止本轮；不为追分无限扩大预算。单次结果是探索性，不能称统计显著。

## 横向比较

实测层：CodeQL、Bandit、可用时Semgrep CE、独立Scout、双引擎旧/新版、Alibaba Open Code Review真实固定实现。所有工具使用相同源码/抽样/CWE口径；缺失CWE无法评分、配置失败、未完成均保留。竞品默认预算无法完全匹配时披露实际调用/工具/token与输入范围。

论文/官方自报层：核实2025–2026一手资料，标注语言、任务、分母、macro/micro、类别映射、模型和预算；不能直接与48例作提升百分比。
