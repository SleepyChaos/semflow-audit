# CQLLM 无RAG提示修订开发验证

2026-10-15，依据用户要求改善无RAG低编译通过率。正式596项批次及接续Vul4Py的冻结实现、提示和结果不变。

## 诊断与改动

v1无RAG最终298项中：100缺@id、58命名空间不合规、1缺@precision，在真实QL编译前被拒绝；124编译命令失败，5模型生成失败，10编译通过。源码抽查同时发现旧TaintTracking::Configuration、未解析类型和QLDoc放在import后的问题。v1已描述元数据和命名空间，但只有自然语言约束，没有确定的文件头和按行生成的接口契约。

独立版本提示 `benchmarks/prompts/cqllm-rule.v2.txt`：

- 明确完整JSON、完整QL文件、固定头置于imports之前；服务器生成audit/cqllm-row-xxxx ID，需求Query_id不再被当作输出ID。
- 增加固定输出契约，避免将不可信需求文本插进注释头。要求problem查询与二列结果一致。
- 提供通用模块化ConfigSig/TaintTracking::Global/Flow::flow写法约束，明确旧Configuration API不适用。该段为所有需求相同的静态接口提示，不做按任务检索、不注入作者标准查询。
- 编译失败时要求返回完整修订结果、保留正确元数据，并保持漏洞需求语义。不自动修正生成代码、不放宽元数据/编译门禁。

此改动针对CQLLM元数据生成评测提示。生产Rule8要求真实源码与检索证据，使用独立rule.v8提示，不能通过切换到元数据提示而绕过生产证据门。

## 预先固定的开发样本

使用原298行，按SHA256(`cqllm-prompt-v2-development-20261015` + row_id)排序，各CWE至多一项，取12项。选择不读历史成功/失败状态：row-0172、0149、0199、0141、0033、0296、0208、0203、0077、0188、0102、0064。跨12类CWE。这些需求已出现在正式批次，属于开发验证，不是独立泛化或统计显著性实验。

v1取同12行既有无RAG回执；v2新调用、独立结果目录，不选择最优重跑。同一冻结app、模型/温度、固定依赖、最多两轮编译反馈和每任务4次请求上限。提示长度及静态接口指导改变，是本轮实验因素；没有检索、隐藏执行反馈或作者答案。三次连续供应商故障停止派发；未提交调用不盲目重放。
