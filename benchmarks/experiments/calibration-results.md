## 2. 实际测试范围与配置

- 完整静态目标 9 个：OWASP Python、RealVuln Flask/DVNA、六个自然 JS 配对的 pre 项目；另有两个有界 QL 派生输入。成功的完整目标各运行三次查询；Angular 查询失败独立保留。
- OWASP 共 1,230 个标签案例：452 正例、778 负例。只跑 CodeQL/Bandit，不对整个 OWASP 执行 Agent。
- 粗筛/复审：两个 RealVuln 开发项目，各一次。修复：一个 systeminformation 模块，旧/新各三次。规则：两个 Python 条件任务，各检索模式三次。
- CodeQL CLI 2.23.5，Python queries 1.6.0、JS queries 1.4.0，均为生产 `code-scanning` suite；2 threads、RAM 2048 MB。未增加扩展 suite。
- 模型请求名称 `deepseek-v4.1-flash`，实际响应 `deepseek-v4-1-flash-260910`；temperature 0，没有发送 seed。重复请求不是新增独立样本，也不保证不同随机种子。
- 各研究模型阶段同样限制最多 12 次调用、240 秒；没有改产品默认预算。语义版多出的调用按真实成本记录。
- 固定公共 RAG 为 1,046 chunks：知识 566、范例 476、未分类 4。向量模型 `doubao-embedding-vision`；没有 reranker。本轮答案、补丁和材料没有导入生产 RAG。
- 测试调用核心工作流，使用私有研究审计记录和源码/数据库根目录别名；未经过 GUI 上传。完整 OWASP 超出当前 2,000 文件上传限制，**不能称全平台上传链路已验证**。
- 没有 GUI、目标服务或下游利用测试。候选修复只在已有 Node 22 Docker 镜像中做无网络、只读、受限资源的模块断言。
- 产品 backend 内容哈希检查未改变；12 份静态记录关联的源码快照均保持一致；普通评分/loader 测试 3 项通过，新增 runner Ruff 检查通过。

## 3. 同输入静态基线：CodeQL 与 Bandit

以下采用自定义 **主文件+精确原生 CWE** 的 testcase adapter；多个告警归并为一个标签案例。不是官方 OWASP scorecard，也没有强行统一不同工具的 CWE 分类。标签外或 CWE 不匹配告警单列，未自动裁成误报。

| 实跑工具 | TP | FP | TN | FN | Precision | Recall | F1 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| CodeQL 2.23.5 / Python queries 1.6.0 | 138 | 150 | 628 | 314 | 47.92% | 30.53% | 37.30% |
| Bandit 1.9.4 / Python 3.14.6 | 108 | 25 | 753 | 344 | 81.20% | 23.89% | 36.92% |

在这个适配口径下，CodeQL 召回高 6.64 个百分点，Bandit precision 高 33.29 个百分点；两者 F1 接近。它们扫描方法和 CWE 覆盖不同，不能据此宣布某工具全面优于另一工具，更不是本平台 AI 增益成绩。

### 速度与失败

| 实跑项目/阶段 | 耗时 |
| --- | --- |
| OWASP CodeQL 建库 | 13.58 秒 |
| OWASP 首次 CodeQL 查询 | 13.33 秒；建库+查询约 26.92 秒 |
| 同数据库后两次 CodeQL 查询 | 4.16 / 4.11 秒 |
| OWASP Bandit 三轮全源码扫描 | 5.76 / 4.39 / 2.64 秒 |
| Flask Scout / 复审 | 25.27 / 29.27 秒；6 / 7 次模型调用 |
| DVNA Scout / 复审 | 29.77 / 7.29 秒；8 / 5 次模型调用 |

这些是实际阶段墙钟；没有清空系统缓存，机器也有其他研究任务并发。首次/同库后续查询分开报告，不据此宣称论文级速度优势。粗筛和候选复审按阶段运行，**没有测产品并发双引擎端到端总时延**。

完整静态项目成功 8/9：Angular 在默认内存配置下 CodeQL 查询退出 99，日志有 Java heap OOM；结果是失败，不是“零漏洞”。两个 QL 派生输入静态执行成功但均零告警，需单独校准入口和参考查询。

### 修正并保留的测试问题

1. 首版 OWASP 匿名化改了 `BenchmarkTest…` 文件名，却遗漏动态 loader 的 `startswith('Benchmark')`。原版 loader 选择 1,230 个案例，错误输入为 0。已另外保存修正版，验证 loader 文件集合双射，再重跑 CodeQL/Bandit；上表只用修正版。旧输入/旧结果保留为诊断。此检查没有声称完整运行等价。
2. 修正版 CodeQL SARIF 记录 1,236 个预期 Python 文件、1,236 个成功提取文件，零 error 通知。源码提取成功与漏洞判断正确分开。
3. 初始 Bandit Python 3.11 有 470 个现代 f-string 解析失败，整轮记 failed。随后保持 Bandit 1.9.4 引擎，在已有 Python 3.14 下重跑修正版，三轮零解析错误；没有把坏环境的漏报当有效成绩。
4. 上游 Bearer 归档不是同源码实跑：132/143 告警片段不匹配当前行，792 当前标签案例显式扫描失败。未纳入工具排名，见 [归档核查](owasp-upstream-comparison.md)。Semgrep 未安装，本批未运行。

## 4. 双引擎：范围扩展成立于线索池，确认阶段仍未成立

| 开发项目 | 正根因 | CodeQL 匹配 | CodeQL+Scout 严格主条件并集 | 最终新增 supported | 未复审候选 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Flask | 14 | 5 | 7 | 0 | 12 |
| DVNA | 17 | 7 | 9 | 0 | 43 |
| 合计 | 31 | 12 | 16 | 0 | 55 |

候选池的暂定根因覆盖从 38.71% 到 51.61%，增加 4 个匹配主根因，约 12.90 个百分点。**这是 evaluator 源码辅助的暂定裁决，非独立人工金标，不能称最终漏洞确认召回提升。** 捆绑 debug 次条件的 17/31 另见逐根因报告，主表不混用。

- Flask 新线索包括硬编码 session secret、明文密码持久化；复审给出 insufficient。DVNA 四批取证遇到读取窗口上限，43 个候选均未完成复审；不能当排除或安全。
- Flask 中未定义的 `rp()` 是上游 FP trap，Scout 把它推测成已绑定危险调用，两个假设来自同一错误根因。需要先核对符号和 import 绑定。
- 未匹配告警保持 unknown，不计算完整 precision/F1；本轮没有 supported 结论，不能从“未误删”推断复审有效。
- 标签在开发阶段已暴露，源码类别标题也未完全去掉，不能称盲测。详情见 [根因核对](discovery-root-review.md)。

## 5. 语义修复：新流程当前有上下文工程回退

对完整 `lib/util.js` 进行候选修复，限定修改目标文件。纯模块 oracle 先校准：原版正常断言 6/6、安全 0/3；官方修复正常 6/6、安全 3/3。安全断言只检查换行、制表符、双引号处理，**不等于完整 shell 注入根因已证实解决**。

| 同一任务、三次重复 | 补丁可评测 | 有界功能+安全联合通过 | 生成阶段中位秒 | 平均模型调用 |
| --- | ---: | ---: | ---: | ---: |
| 旧 v1 | 3/3 | 3/3 | 3.04 | 1.00 |
| 语义 v2 | 1/3 | 1/3 | 32.80 | 6.33 |

v2 两次明确失败：`关键上下文超过预算，需缩小目标；未截断原文`。保守拒绝保住了完整证据边界，但重复语义取证/上下文组织妨碍了实际补丁生成。另一次 v2 联合通过，说明并非所有语义调用都无法运行；当前未表现出比旧方案更高的可靠性。

这一分数来自 **一个模块×三次请求**，oracle 是 agent-authored、未人工复核，输入是评测器提供的已知候选，不是最终审计驱动的整项目修复。没有完整业务语义保持或“无新漏洞”证明。

四组上游模块候选的筛选也实际执行：express-fileupload 另一个原型路径仍失败；phantom 的 mock 合同存在环境歧义；forge 官方删除 API 不符合保持 API 的任务定义。当前只得到一个有限合格候选，正式人工复核合格任务仍为 0。见 [oracle 校准](repair-calibration-report.md)。

## 6. RAG 与规则：检索可用不等于规则有效

### 生成结果

任务为 OWASP 派生 SQL 注入和代码求值两类；每类给一个正例源码及 helpers，另留两个正例、两个负例给评测器。隐藏源码/结果不回流 LLM。它们不是两个完整项目，也不是跨仓库迁移任务。

| 请求的检索模式 | 运行数 | 编译+开发验证并持久化 | 隐藏实际评测 | 隐藏联合通过 | 未进入隐藏评测 | 生成中位秒 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| BM25 | 6 | 2 | 2 | 0 | 4 | 56.90 |
| 向量 | 6 | 2 | 2 | 0 | 4 | 57.52 |
| 混合 | 6 | 1 | 1 | 0 | 5 | 60.41 |
| 合计 | 18 | 5 | 5 | 0 | 13 | — |

五个持久化规则均来自 SQL 任务，每次隐藏评测 TP=0、FP=0、TN=2、FN=2；没有正例检出，因此不能拿“无误报”表示有效。其余 13 次是生成/验证失败，未运行隐藏评测，不伪造它们的 FP/TN。

- 五个规则在开发项目单规则扫描也为零告警；因为本次入口没有 Candidate，产品 `project_replay` 明确是 `not_evaluated`。开发自造样例通过仍可留下规则草稿，说明验收门槛不足。
- 有界输入没有完整 app loader，需用经过校准的参考 QL 和入口模型确认任务可解；现阶段不能把 0/18 推成所有真实项目的 RAG 准确率，也不能全部归因检索方式。
- 有效草稿接近官方通用 SQL 模板，没有验证出针对源码 helper/API 的新增覆盖。生成代码可编译、引用真实知识、针对目标漏洞有效是三个验收项。
- 当前响应契约要求至少一个 knowledge ID，因此 NoRAG 控制不支持；本批把它登记为未运行，没有伪造知识/零分。没有完整四组 RAG 消融。
- 生产检索的角色路由部分强制使用 BM25，所以表中是“请求模式的完整生成流程”，不是纯向量对纯 BM25 的严格因果比较。
- 本批与旧 18 次合成小样例任务、输入、指标不同，禁止与旧 15/18 直接相减。

### 独立检索结果

20 个查询覆盖 10 个 CWE×Py/JS，同样的固定公共语料，每次取三个资料和两个范例，三模式共 60 条记录，全部成功返回。

| 模式 | 查询成功 | CWE 范例元数据匹配/范例槽位 | 数据库检索中位秒 |
| --- | ---: | ---: | ---: |
| BM25 | 20/20 | 29/40 | 0.335 |
| 向量 | 20/20 | 28/40 | 0.322 |
| 混合 | 20/20 | 29/40 | 0.331 |

元数据匹配不能衡量 API/语言版本适配、知识是否足够解决需求。尚无人工相关性 qrels，未计算 Recall@k/nDCG/MRR；数据库耗时不包括完整 embedding API 时延。**本批不能得出 BM25 优于向量的结论。** 后续独立标注检索，再固定证据比较生成。

## 8. 成本、结果留存和下一步

本批三个模型链路累计 **99 次文本模型调用、681,097 输入 tokens、99,199 输出 tokens**，总计 780,296；失败调用纳入计数。独立检索另有 20 次 embedding 请求；生成阶段 embedding 用量未完全汇总，未算进文本 token 数，也没有按未知价格估算金额。
