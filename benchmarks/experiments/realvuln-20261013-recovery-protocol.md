# 第二次断网后的窗口接续与复核补测

2026-10-13。用户确认第二次异常仍因临时断网，并明确要求再次重试和最终能力结论。

统一 v2 全量实验已尝试完 26 个项目，CodeQL 26/26 成功，报告和原始失败阶段均保留。随后四项目 v3 补测中，OWASP 完成取证，但 PyGoat、Python App、Python Insecure App 再次遇到网络失败；v2 最后的 VulnPy、Vulpy 复核也因超时中断。因此恢复范围事先确定为这五个项目，不按漏洞命中选择恢复项目。

新恢复目录 `artifacts/research/realvuln/20261013-progress-v3-recovery` 的 app 实现与 v3 补测一致。模型、提示、数据集与源码固定。每个项目沿用其独立 audit_id，在该审计内创建新的阶段；旧阶段、账本和证据不可变。未完成初审使用生产补审入口同一服务的 `continuation_inputs` 与冻结地图，只调度失败/未访问的可审窗口。已完成窗口继承，旧候选保留；导出按 hypothesis identity 合并谱系候选，不丢弃旧证据。谱系不得跨审计或混入非初审阶段。

初审已完成的 VulnPy、Vulpy 复用原初审结果，只新增复核；已成功 CodeQL 的快照、CLI、套件与查询包核验后复用。新 result.scout_usage 与时间只计算新增执行，复用阶段为零增量；旧完整 usage 仍在原 scout.json 中，不能在成本汇总重复计入。

恢复项目并发 2。停止限流或断网阶段后不自动持续付费重试；本次恢复基于用户显式再次授权和连接检查恢复证据。新执行仍保留请求超时、局部取证步骤、结构恢复限制和真实无进展保护。

最终给出三种互不混淆的结果：原配置全 26 项目；统一 v2 全 26 项目（含网络失败）；指定项目恢复后的增量全量汇总。后者由 20 个 v2 项目、1 个 v3 OWASP 补测和 5 个 v3 网络恢复项目构成，不是统一新实现全 26 项目重跑，也不按单条标签择优合并。未决、协议失败、缺失证据和延期范围单独报告。

本轮中途对话中断终止了执行进程，核验无后台进程后，从 PyGoat 初审与 VulnPy 复核的原 stage_id 检查点接续。保留原 usage 和批次/窗口回执，已冻结成功调用复用；中断事件单独记录。两个接续阶段 wall_seconds 仅包含恢复后的运行片段，不用于总耗时比较，token 与调用数保留完整账本。最终五项目均产生回执，复核 stop_reason 均为空；证据不足与剩余窗口仍明确标为未决或部分覆盖。
