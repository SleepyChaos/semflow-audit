# 代码审计优势来源：互补发现、前提复审与反馈补证

版本：2026-11-02 / v1。用户授权的研究方向限定于代码审计模块。RealVuln 10-14 结果用于历史诊断和开发回归；本协议的机制对照不是那次六组实验已经完成的部分。

同日后续实现：本地已接入受限补证v1，可通过Review输入`supplement_insufficient=false`关闭作对照；机制和工程验证见[反馈补证文档](../../design/audit-mechanisms-20261102/evidence-feedback-20261102.md)。新增机制的RealVuln模型效果实验尚未执行，原始结果不改写。

## 研究边界与当前状态

研究问题：系统最终的收益分别来自发现覆盖、证据推理、弃权过滤，还是检索补证？这三部分对同一批根因的增益和损失如何传递到最终结果？

本轮完成 26 项目历史回执诊断、3 项目保存请求诊断和 DVGA 四组输入预检。新模型调用、扫描和动态利用次数均为 0。完整冻结源码目录缺失，保存上下文重放与完整管线重跑分别登记。

本研究状态单独保存在 [audit-mechanisms-state-20261102.json](audit-mechanisms-state-20261102.json)，保留旧 `state.json` 的修复实验历史。

## 一、静态分析与语义审计的互补发现

对象首先是独立 A/CodeQL 未命中、独立 B/Scout 命中的 309 个金标；另建 Scout 未匹配候选队列，不能只研究命中案例。人工核查单位为源码中的安全条件/根因，官方金标 ID 仅用于评价映射。

四个解释轴允许同时存在，不强行互斥：

| 解释轴 | 必须取得的证据 | 不能据此推断的结论 |
| --- | --- | --- |
| 规则覆盖 | 实际运行 suite、pack/query ID、查询语义与目标缺陷是否对应 | 没有告警不能证明没有覆盖规则 |
| 语义理解 | 同一可见源码中输入、数据/控制路径、业务要求和防护条件的独立裁决 | Scout 命中或文字描述复杂不能证明语义优势 |
| 输入范围 | 上传过滤、扫描语言/提取文件、DB 构建错误、候选窗口和实际模型页 | 扫描成功不能证明每个目标文件/路径均已提取 |
| 评分/分类 | 固定官方匹配器下的位置、CWE、可接受替代位置、贪心分配及重复身份 | 评分新增命中不能直接算新增根因 |

本轮自动输出仅包含可直接核验的位置/CWE信号。309 个中有 34 个附近存在其他 CWE 的静态输出、275 个附近没有静态输出；两类均待以上四轴核查。

后续对照保留生产默认 suite 和固定源码为主组。规则扩展、扩大提取范围和统一 CWE/根因归并分别作为诊断组，不覆盖主组成绩。对同样输入的静态与 Scout 输出盲化来源后裁决，记录证据路径、主因/次因、不确定及裁决分歧。

指标：独立交集/各自独有命中、人工确认补充根因、Scout-only 真实/非漏洞/未决比例、每新增根因成本。同时报告按金标的 micro 指标和按项目的分布；官方计分、去重复根因和人工真值三张表分别保留。

## 二、基于漏洞成立条件的证据复审

固定合流 C 的候选池及安全属性；发现阶段不随复审配置改变。正例、负例与未决都进入分析，不能把尚未证明的候选作为安全反例。

统一证据账本：

| 核实项 | 记录内容 |
| --- | --- |
| 可控输入/可达性 | 真实入口、攻击者可控值、认证/身份前提、赋值与分支是否改变最终值 |
| 危险操作 | 实际语句、符号绑定、操作对象、相关调用/框架语义 |
| 有效防护 | 校验、编码、参数化、守卫、中间件的实际作用范围与是否阻断该路径 |
| 业务授权要求 | 身份/角色/对象归属分别证明；来源是实际契约、源码要求，或仍未知 |

现有实现将前两类按目标属性折叠到 `operation` / `input_or_policy`，防护落在 `unsafe_protection`。实验标签保留四项，避免把“公开接口”和“缺少保护”本身当成需要认证的业务要求。每项区分事实、引用、推导和未决，引用真实并不等于推理成立。

复审消融至少比较：仅引用/位置校验；结构化前提复审；结构化前提加证据与结论的独立一致性核查。最后一项尚待实现和校准，不把再次询问同一模型当成人工真值。

每种配置固定候选、初始证据、模型、响应 schema、分类策略、预算与失败规则。语义判断主分析固定候选原始位置/CWE；模型重新分类的正式输出另报，防止把 CWE 收窄的计分收益混作推理改善。

指标：确认误报被正确排除比例、真实根因保留率、误排除/转未决损失、已决覆盖率、未决率、前提正确率、引用与推导一致率、条件性 precision 与全量 recall。未匹配 FP 另列为评分现象，人工没有裁决的保持未知。报告最终 precision 的同时必须给出未决数量与召回损失。

## 三、发现与复审之间的反馈补证

反馈的操作顺序是：

1. 将未决结论中的缺失前提绑定到候选 ID、属性、缺失事实及所需证据位置。
2. 先核对当前请求，再查同一不可变快照/阶段的已有证据；有相关页时检查是否足以回答该前提。
3. 已有页仍不完整时，定向读取关联函数、中间件、挂载配置或真实业务契约；没有政策证据时保留政策未知。
4. 用新增或重新定位的实际证据重新判断。保留原结论、输入哈希、证据 ID、前后状态、消耗与停止原因。
5. 同一缺失事实重复、预算耗尽、源码不可得、证据矛盾或策略无法确立时停止；停止不等于排除漏洞。

先做一个完整可核验的小对照，再扩展真实工具循环：

| DVGA 保存上下文重放组 | 明确提示重新核对缺失前提 | 补入先前已读的中间件/视图证据 |
| --- | --- | --- |
| R0 | 否 | 否 |
| R1 | 是 | 否 |
| R2 | 否 | 是 |
| R3 | 是 | 是 |

四组使用同样三个未决候选、同样已有证据正文、相同导航压缩及单次最终判断。R2/R3 只补入原阶段第 31 次调用之前已出现的三页，引用原 ID 和原 digest；不引入未来调用的证据或金标答案。R1/R3 给出缺失前提角色，不向模型提供期望 verdict。该对照分开检验重新核对与证据供给，不是自动工具闭环已经实现的证明。

保存的 `dvga-replay/preflight.json` 限定：4 组、每组至多 1 次提供商请求、每次输出上限 6000 tokens、超时 90 秒、0 自动重试、1 次开发重复。四组输入分别为 27884/28406/39165/39687 字符，上限 40000。该上限是字符数；提供商输入 token/保留上界和实际消耗必须另外记录，不能把字符当 token。当前输入准备完成，尚未执行模型实验。

执行前完成源码事实参考裁决和模型身份/schema 冻结。DVGA 原 `core/views.py` 501–525 行未恢复，业务策略仍可能未知；这类缺口不能通过补入另一个中间件文件就视为解决。模型版本与 10-14 的响应身份不同则登记新实验，不能把历史输出作为同模型随机对照。

真实循环的下一阶段比较：原有按需读取；同一预算的重复判断；缺失前提定向补证；同预算非定向补读。取证共享全阶段调用/token/时间总额，每个候选限制反馈轮数和页数，所有 provider 重试计入限额，断点恢复不能重新获得预算。当前实现只为未获有效评估者做恢复；扩展到有效 `insufficient` 是待验证的新机制。

指标：未决→正确支持/正确排除/仍未决/错误决定的转移；每个已解决前提和正确解决候选的新增成本；同预算真实根因保留；已存在页复用率、相关新页获取率、获取后使用率、真实补证失败原因。仅未决率下降不足以证明改善，错误强行决断必须计入。

## 整体效果与论证要求

三部分共享同一稳定候选/根因身份，记录静态/Scout 的来源、复审前后与反馈前后的完整转移。最终端到端对照沿用 A/B/C/D/E/F，内部机制采用固定候选池消融，避免同时改变发现范围、模型、预算和分类。

现有六个案例与26个项目已暴露于调试，只用于开发解释与回归。正式效果需在独立预留项目按项目分组、覆盖负例和弃权、锁定配置后重复；小 pilot 不作显著性或泛化结论。报告失败、未知成本、未决及缺失源码，禁止只挑 TP 增加的项目逆推创新已经成立。

当前可支持的机制描述：静态与语义发现具有观察到的互补；前提复审提高匹配输出 precision 同时损失 recall；按缺失前提组织反馈是已找到工程缺口后的可检验改进。尚不能声称三项均有因果实验证明或已构成论文创新。
