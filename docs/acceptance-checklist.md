# 用户校准清单

2026-10-03。以下项目供用户手动验收，均保留未勾选；开发过程只执行代码/API/CLI 测试，没有 GUI 测试。代码与真实工具验证结果见 research/benchmark-results.md。

## 启动和配置

- [ ] 登录 http://localhost:5173，账号密码取本地 `.env`，不在聊天/仓库传播。
- [ ] API、Worker、PostgreSQL、Redis 均可用；CodeQL 两个固定查询包和源库已安装。
- [ ] 在 `.env` 配置真实 AI 网关/模型/密钥并重启 API、Worker；模型能力显示符合配置。
- [ ] 选用向量服务时索引成功；没配置时明确使用 BM25，不显示虚构语义检索结果。

## 第一阶段：CodeQL

- [ ] 上传 Python、JS/TS ZIP，选择项目名/语言/已发布补充规则。
- [ ] 正常显示建库、扫描、告警、源码、数据流、日志、快照/工具/包版本和 SARIF。
- [ ] 错语言、破损 ZIP、越界路径、超限文件明确失败；失败不显示“零漏洞”。
- [ ] 取消/失败重试保留原执行，创建新 ID；取消为外部调用结束后停止。45 分钟无更新可回收。
- [ ] 其他账号不能访问本用户源码、产物、知识、规则或阶段记录。

## 第二阶段：AI 复审

- [ ] 选择告警、路径、补充发现开关与取证预算，观察阶段历史、调用与 token。
- [ ] 候选能查看实际源码/查询/知识证据的位置、快照和 digest，模型建议不自动变为确认。
- [ ] 人工确认/排除需理由与代码/查询证据；证据不足可保留待定或弃权。
- [ ] 重复复审不增加同一实例计数；不同位置仍需人工核实根因是否独立。
- [ ] 测试跨文件调用、良性 eval、伪指令注释、无知识命中、服务超时；判断边界符合研究需求。

## 第三阶段：修复与报告

- [ ] 只选已确认候选，可设修改文件范围、验证配置和复扫。
- [ ] diff 仅修改副本；原始源码哈希未变。修改原因、验证输出和复扫均可看。
- [ ] 通用语法通过不被当作功能正确；TS/JSX 编译缺失、零 JS 测试进入待复核。
- [ ] 检查通过后能人工接受；接受保存记录，不直接覆写原项目。失败补丁保留。
- [ ] JSON/Markdown 报告有原始告警、候选状态、证据、判断历史、补丁、规则/知识版本和覆盖边界。
- [ ] 用真实安全与原功能测试校准补丁；确认是否需要后续增加项目专用验证镜像。

## 第四阶段：RAG 规则

- [ ] 导入知识能查看来源、版本、索引状态与真实检索片段。
- [ ] 选择需求、生成策略和确认缺陷后，查看引用、固定依赖、QL/.qll与编译反馈。
- [ ] 人工等待释放 Worker；未经批准正反例不能运行验收/发布。
- [ ] 正例/负例可查看文件、期望位置、语法和实际结果；未通过不能发布。
- [ ] 已发布规则可在新扫描中显式选择，SARIF保留基线与补充来源；退役不修改旧版本内容。
- [ ] 独立留出变体与良性近似例校准泛化，不以模型自生成一正一反证明质量。

## 论文与基准验收

- [ ] 阅读 experiment-plan.md，确认三项机制与研究主线；不将功能名称直接当原创。
- [ ] 校准已下载材料、许可、完整快照/oracle状态、2025/2026论文引用。
- [ ] 检查 benchmark-results.md 原始路径；微型样本、真实CVE探索、模型测试替身成绩分开。
- [ ] 确定真实模型、预算、主CWE、完整项目数量、标注者与测试集切分。
- [ ] 确认还需研发的论文机制：独立规则留出、根因去重、通用双oracle注册、受控知识回流。


## 真实模型测试后需重点校准

- 输出不完整或缺少真实位置时显示失败/未知，不显示安全。
- 模型建议与用户确认分开；锚点不是漏洞；未证实的new_location不是增量收益。
- 修复分别展示安全测试、功能测试、复扫与人工验收；本轮5个通过独立测试的补丁仍是needs_review。
- RAG显示实际BM25方法及引用版本；本轮未配置embedding，未发布3条研究草稿。
- 同名eval的XSS与代码执行标签分开；修复和报告不要只看候选数。
- 完整证据与改进安排见 docs/research/live-model-results.md、improvement-plan.md。本轮未操作GUI。
