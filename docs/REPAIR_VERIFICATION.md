# 通用修复前后验收

这项功能属于独立工作台 `D:\semflow-audit-ui`。原项目保留。支持 Python（pytest）和 JavaScript / TypeScript 项目中的可执行 JavaScript 测试（Node test runner）；TypeScript 的编译和所需依赖须预先放进项目验证镜像。

## 操作

1. 在 AI 复审中核对源码证据，人工确认要修复的缺陷。
2. 在“修复与报告”勾选这些缺陷，填写需要保留的正常业务行为和项目镜像，点击“AI 生成验收测试草案”。也可以导入团队已有测试集。
3. 选择生成后的固定测试集，阅读中文的输入与预期，展开检查测试代码。AI 草案的业务预期可能有误；需要修订时生成或导入新版本，旧版保留。
4. 生成修复 Diff。选了测试集的修复在补丁生成及已有检查结束后，自动排队执行前后对比。已有补丁也可以点击“运行修复前后对比”。
5. 阅读每项测试的原始和补丁后结果、两轮记录、代码改动。全部必要检查达标后，填写审阅理由并勾选“已审阅测试断言和前后结果”，才能接受补丁。接受与下载不改写上传的原始代码。

## 怎样才算达标

平台执行相同测试文件、相同输入与断言、相同镜像摘要，原始和补丁副本各运行两轮。

| 检查 | 原始代码 | 补丁副本 | 判断 |
| --- | --- | --- | --- |
| 安全测试 | 安全断言失败 | 安全断言通过 | 该输入复现的风险被阻断 |
| 正常功能测试 | 通过 | 通过 | 该业务输入的行为保持 |
| 安全测试原本就通过 | 通过 | 通过 | 未复现，证据不足 |
| 导入错误、缺依赖、跳过、遗漏或超时 | 任意 | 任意 | 证据不足，不能接受 |
| 原功能通过，补丁后失败 | 通过 | 失败 | 验证未通过，检查补丁或测试预期 |
| 两轮结果不一致 | 任意 | 任意 | 证据不足，检查不稳定因素 |

每个所选修复目标都需要关联至少一项安全测试；还必须有正常功能测试。语法检查和所选 CodeQL 复扫仍需达到原来的检查条件。AI 独立发现未必有对应静态规则，因此 CodeQL 无告警本身不能证明修复。

结果保存在新的 `verification` 阶段和 `comparison.json`，不会把旧“环境缺失”“语法通过”记录改成成功。源码、补丁、Diff、测试文件或验收材料变化后，旧结果失效。人工审阅绑定当前对比记录；重跑后要重新确认。

## 镜像如何准备

镜像是运行依赖环境，可以由多个依赖相同的项目复用，不必每个漏洞生成一份。平台不会在测试时联网安装依赖，也不会自动拉取镜像。

- Python：需要 Python、pytest，以及项目实际使用的依赖。平台基础镜像为 `ai-code-audit-validator:local`。本地 Flask 演示使用 `ai-code-audit-validator:flask-demo`（另含 Flask 3.1.2）。
- JavaScript：需要 Node 和实际项目依赖。基础镜像配置为 `node:22-bookworm-slim`。测试从 `/workspace` 导入真实模块。
- 在“项目验证镜像”填本机已安装镜像标签；留空使用平台 `VALIDATOR_PYTHON_IMAGE` / `VALIDATOR_JS_IMAGE` 配置。实际运行会固定镜像摘要。
- 验证容器使用只读源码与独立只读测试集、临时目录、无网络、非 root 和资源限制。需要数据库、网络服务、可写项目目录的测试目前可能无法执行，应如实补齐适配能力，不能用 mock 安全行为或跳过测试获得通过。

## 团队测试集导入

导入 JSON 的外层为 `{"image":"已安装镜像标签","suite":{...}}`。`suite` 包含：

- `title`、`summary`：中文说明。
- `language`：`python` 或 `javascript`。
- `files`：文件名到代码内容的映射，只允许独立测试文件。Python 使用 `test_*.py`；Node 使用 `*.test.cjs` / `mjs` / `js`。不得修改项目文件。
- `cases`：每项包含 `name`（真实且唯一的 `test_...` 测试名）、`category`（`security` 或 `functional`）、`candidate_ids`、中文 `input_description` 和 `expected_behavior`。
- `assumptions`：中文测试前提和未覆盖范围。

候选 ID 必须来自同一项目且仍为已确认。安全用例必须关联候选；功能用例可以不关联。暂不支持参数化、嵌套或动态生成用例名，避免缺失测试被当成完整验收。平台固定测试文件、配置和 Node 结构化报告器的指纹。

接口：`POST /api/v1/audits/{audit}/verification-suites/generate`、`.../import`、`GET .../verification-suites`、`POST /api/v1/repairs/{repair}/verify`。修复请求可带 `verification_suite_id` 自动执行；接受请求必须带当前 `comparison_stage_id`、`test_reviewed: true` 和审阅理由。

## 中文报告及验证范围

对比结果进入 AI 中文报告材料。执行或修复结果变化后，旧报告标为过期，点击更新报告即可让 AI 结合新证据解释漏洞位置、修复方法、已执行的检查和剩余风险。AI 的解释不能改写主机执行结果或人工决定。

通过只意味着所列测试断言达标，不能证明所有路径或生产部署都安全。AI 生成的测试尤其需要检查“是否测到真实入口、断言是否正确、正常业务是否定义清楚”。本地 XSS 演示使用实际 Flask 请求和 HTMLParser 检查响应；没有声称执行了真实浏览器攻击，也没有声称完成生产验证。

2026-10-11 实际检查：Flask 演示先生成 AI 草案，随后新隔离补丁自动执行两轮 7 项测试（2 安全、5 功能）达标；另一 Python 数字转换项目和 Node 转义项目使用相同平台 runner 各执行两轮达标。第一份 AI 草案错误地要求引号在 HTML 源码中保持原字节，实际比较未通过并保留记录；明确显示文本的业务要求后创建新测试集，没有改写旧版或隐藏失败。
