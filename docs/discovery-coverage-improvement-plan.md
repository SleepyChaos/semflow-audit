# 双引擎输入与检查覆盖改进

日期：2026-10-06。基于上一轮开发集复测；本阶段先解决没有输入、没有检查、没有明确检查任务。暂不扩展CodeQL suite、不更换模型、不改修复/RAG链路。

## 改造与目标

1. 源码清单、搜索和候选定位纳入EJS/HTML/Jinja等模板及项目配置。继续拒绝凭据、依赖工作目录及越界读取。目标：模板中的输出安全问题能够进入独立粗筛和复审。
2. 使用稳定的业务优先调度：入口/认证、业务处理、模板、配置、其他源码；优先级内先各文件首窗口再深入；入口/认证/处理函数优先级的后续页先于大量模板。第三方/生成文件保留清单但默认延后，不把延后写成安全。分配调用额度，最后一次必须提交结果或未知。目标：有限预算减少被重复取证及第三方文件消耗。
3. scout.v5按安全属性分配任务，记录认证、授权、对象归属、输入、输出、状态、秘密配置、审计/防滥用检查；任务状态与漏洞确认分开。目标：已检查窗口没有悄悄遗漏检查维度，独立安全条件单列候选。

## 验证

- 普通测试：模板发现→取证→候选→复审；凭据隔离；业务排序；预算覆盖；检查任务遗漏/虚构证据拒绝；旧版本恢复。
- 同源码/同模型对照：归档scout.v3 vs v5的8窗口/12调用粗筛，比较输入、覆盖、候选主根因及费用；声明新版扩大输入，不能只归因提示词。
- 完整业务覆盖实验另列预算：scout.v5→review.v7，固定CodeQL套件；保留未决、未映射和运行失败。新root须源码辅助逐项关联，不靠CWE/行号自动匹配。全部为开发校准，非人工金标/服务利用确认/论文复现。
- 新批次保留源码/实现/提示/配置哈希、调用账本和启动收据；旧付费批次不重跑。无GUI、目标服务或漏洞利用执行。
