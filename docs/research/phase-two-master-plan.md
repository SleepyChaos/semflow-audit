# 下一阶段总计划：规则生成、审计效果、审计速度

制定日期：2026-10-03。状态：执行中，已完成工作包 A 和首批 B/C/D 试验。起点：`6e7a0a1`，上一阶段结果见 [消融报告](rule-generation-ablation-results.md)。本计划中的目标是待验证目标，不是已取得的成绩。本轮完成与未完成项见 [首批结果](phase-two-results.md)；切换模型前的历史记录见 [交接记录](phase-two-handoff.md)。

## 1. 目标与边界

统一研究问题：项目语义证据如何增强静态分析，并在可控成本下改善审计结果？主线只有三条：规则生成、审计效果、审计速度。修复与安全/功能双 oracle 保留为结论验证工具；本阶段不扩展语言、不重做 GUI、不训练模型。主范围 Python、JavaScript；TypeScript 单列提取与工具支持率。

每个改进遵循：失败证据 → 原始论文/官方方法核实 → 可证伪假设 → 冻结基准和对照 → 最小实现 → 普通测试 → 真实工具/模型实验 → 决定保留、回退或继续探索。论文数字不能作为本平台指标，模型替身只验证程序行为。优先 2026 文献，补充 2025；基准允许使用更早的成熟真实漏洞。

## 2. 起点与研究假设

| 方向 | 已有证据/缺口 | 假设及改进目标 | 验收口径 |
|---|---|---|---|
| R1 规则生成 | 162 次可比较生成请求；执行反馈使标准组 9/18→15/18，模拟 API 组 3/9→8/9；真实跨项目证据不足 | 版本化文档＋项目 API 绑定＋受限规格＋执行反馈，提高未建模 API 规则的可执行、可泛化成功率 | 全请求端到端通过；编译/开发/隐藏通过分别报告；新增覆盖与官方复用分开；无证据拒绝率与 OOD 支持率 |
| R2 审计效果 | 微样本可用，真实 AI 复审仅少量固定场景；无法证明整体 precision/recall | 数据流与跨文件证据约束下的复审/主动调查，减少误报、保留 TP、补充独立确认的 TP | 根因级 P/R/F1、TP 保留、FP 去除、弃权/未决、工具失败、新增 TP；独立金标或双 oracle |
| R3 审计速度 | 规则反馈提高质量也增加耗时；缺少统一时序与相同输入对照 | 数据库与证据复用、查询批处理和按风险分配预算，在质量约束下节省总耗时/调用成本 | 各阶段时间、总时间、吞吐量、调用/token、首次/重复/增量分列；质量-耗时曲线 |

方法依据：IRIS（ICLR 2025）的 API 规格/上下文复审，QLCoder（ICLR 2026）的工具反馈与执行检查，CodeRAG-Bench（NAACL 2025）的检索/生成分开评价。实际阅读与适用边界见 [原规则论文阅读](rule-generation-paper-review.md) 和 [本阶段文献核实](phase-two-literature.md)。速度的设计推断必须经本机固定条件验证，不能从其他系统论文直接转用加速比例。

## 3. 工作包和交付门槛

### A：流程固化与可测量性（首先执行）

- 将生成、契约/编译、开发样例执行、反馈重试、持久化拆成 LangGraph 节点；单次候选与诊断保存在不可变尝试目录，节点状态传递引用。
- 维持最多两次候选尝试及统一模型预算；取消检查位于节点/外部调用边界；开发反馈不得获得隐藏测试内容。
- 记录节点状态、单调时钟耗时、尝试编号；失败、取消、人工暂停分别计入，暂停不能当计算时间。
- 兼容既有 prompt/历史阶段与人工批准、独立验收、发布门槛。先保留原生成策略为对照；新规格策略的 GUI 默认切换在真实基准通过后执行。
- 验收：编译失败反馈、执行失败反馈、最多两次、取消阻断、暂停恢复不重复调用模型、隐藏标签隔离测试；真实 CodeQL 图烟测。此烟测不作为真实 LLM 质量成绩。

### B：规则的真实语义扩展

- 分清 `baseline_reuse`、`model_extension`、`new_detector`；基线已有能力直接复用。
- 从项目 API 清单与检索证据约束模块/成员/参数，先处理已发现的 Flask get/post 覆盖问题；先核对固定库与框架文档，再实现模型。
- 从当前 Python 代码注入 sink 扩到 source/summary；每一类先做正反例。sanitizer 不自动放宽，独立证明后另行支持。
- 先形成至少 20 项规则需求，每项目标至少 5 个隐藏正例、5 个近似负例；已有 6＋3 任务标为开发/回归，不冒充全新留出。
- 对照：原生 CodeQL、人工正确模型、无 AI 的文档提炼、自由 QL、受限规格、移除领域知识、移除执行反馈。固定模型/调用预算，报告实际花费；重复运行衡量稳定性，独立任务衡量泛化。
- 决策门槛：相同独立样本上端到端成功提升、没有新增未解释误报、失败全部可追踪；未通过时保留实验开关，不默认替换。

### C：真实审计效果基准

- 先选择 20 个真实漏洞/补丁配对（目标 Python/JS 各 10，至少 4 CWE），验证材料、抽取与评分流程；不足时透明列出缺口，不降低真值要求凑数。
- 再扩大到 60–100 对、至少 10 项目。仓库/漏洞家族切分；同一上游 fork、补丁近重复属于同一组。
- OpenSSF/Vul4Py 用于真实配对；SastBench 用于告警复审；RealVuln 用于项目级覆盖；VulnGym 用于路径证据；AACR 仅经安全类筛选后作为复审辅助。各基准分别评分，不直接混合不同任务标签。
- 每项保存原始来源、许可、commit、源码 SHA、根因/CWE、原版/修复版、标签依据、是否完整仓库、oracle 状态、split、纳入/排除原因。补丁与 trace/rationale 只供评分器，不供生成模型。
- 对照：固定 CodeQL；Bandit（Python）；Semgrep CE 与明确规则集；同一 LLM 直接审计；平台＋复审；平台＋主动调查；平台＋模型扩展。阿里 Open Code Review 作为独立工具对照，输入范围、模型预算与版本分别披露。
- 漏洞匹配按根因/路径/CWE，避免仅按行号；对未匹配告警保留原基准分数及独立复核结果两份表。未裁决不能被写成 FP 或安全。双人标注/第三人仲裁是正式论文要求，当前未完成时明确标注。

### D：质量约束下的速度优化

- 固定硬件、并发、CLI/packs、模型、提示词、预算、样本顺序，分别记录 queue/extract/query/retrieve/model/evidence/validation/report。
- 首次提库、同快照复扫、修改后增量分开；OS 缓存未清空时不宣称严格冷启动。首次编译和后续执行分开报告。
- 优化顺序：计时 → 同快照数据库复用 → 查询批处理/证据去重 → 风险预算 → 增量依赖与失效策略。模型生成规则成本单列，并按复用 1/5/20 次计算摊销。
- 禁止恢复已出现串用的动态 BQRS 身份缓存。缓存键包含源码、CLI、依赖、查询/模块、配置及相关模型版本；每个优化必须与完整重算做差分一致性检查。
- 首批每配置至少 3 次，正式性能组至少 5 次；报告中位数、范围与样本量，小样本 P95 仅描述性。模型失败也纳入成本。
- 先冻结质量基线再声明速度目标：工程探索目标为总耗时/模型成本降低约 20%，但不得因此丢失当前金标 TP；正式非劣效界限须在测试前预注册，样本不够时不声称统计非劣效。

### E：论文级汇总

- 任务级配对比较、项目级 bootstrap 区间；样本不足不写显著性。报告按 CWE/项目/语言的宏平均和总微平均。
- 保留负结果、执行失败、预算耗尽和协议偏差；任何模型/提示词/标签改动建立新实验 ID。
- 产出可复现命令、环境/材料 manifest、原始结果索引、三轴消融表、局限与威胁分析、用户 GUI 校准清单。
