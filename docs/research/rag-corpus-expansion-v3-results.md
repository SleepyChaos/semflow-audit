## 2. 扩大了哪些内容

- 漏洞范围：代码/命令/SQL/NoSQL/模板/LDAP/XPath/正则注入、路径遍历、反射/存储/DOM XSS、SSRF、反序列化、XXE、重定向、原型污染、敏感数据处理、凭据及密码学、资源耗尽等。

这批主要增加固定版本的 CodeQL 建模知识与完整示例。**漏洞原理教程、框架业务行为说明、编译修正案例和安全反例仍需要补充**，不能把“更多 `.qll` 原文”当成完整的知识体系。

当前共有 702 个公共切片具备匹配的向量身份，其中还包含历史版本；严格有效来源规模应看本批清单的 **271 个知识来源＋135 个合格范例**。现有 BM25 过滤仍允许部分历史未验证范例，后续应建立当前有效来源视图并按版本/内容去重，保持历史记录可追溯。

## 4. 校验、索引和检索结果

1. 使用已有本地公开 MIT 官方包；每个新增原文与固定 Git tree blob 核对，依赖版本锁定，未采集用户上传源码。
2. Python 新增 30 个、JavaScript 新增 83 个完整范例，最终都通过真实 CodeQL 隔离包编译检查。首轮为 112/113；采集脚本漏了一个 `private import` 辅助模块，补齐精确官方模块后单条复查通过。初次错误日志保留，没有改写官方查询逻辑或测试金标。
3. 批量检查已明确成功的 82 个 JavaScript 范例保留原日志和源码哈希；停止冗余逐条重查后，只补查缺依赖项。恢复 receipt 与原始批量日志保存，不将未检查的条目记成成功。
4. 用配置中的真实 `doubao-embedding-vision` 索引，沿用当前模型版本/2048 维和身份校验；**索引失败 0**。原 6 个开发测试失败范例继续排除。
5. 在固定 v3 文档 ID 范围内，做两语言 × 10 CWE 家族 × BM25/hybrid，共 **40 项材料可用性检查**：BM25 **18/20**、hybrid **18/20**，合计 36/40。检查两集合非空、固定版本和完整范例取回；没有人工相关度金标，不能称检索准确率，也不能证明向量优于 BM25。
6. 源码身份篡改拒绝、循环/私有依赖闭包、部分批量失败不冒充全部通过等普通测试 **3 项通过**；Ruff 与 diff 检查通过。

### 检索缺口

两个模式均在 JavaScript SQL（CWE-089）与 NoSQL（CWE-943）缺少合格范例，参考知识并非空：

- 官方 `SqlInjection.ql` 同时导入 SQL 与 NoSQL 数据流，标记 CWE-089、090、943；它在上一批官方开发测试中失败，本批维持排除。
- 当前 provenance/过滤只用所在目录的单个 `cwe` 字段。即使对应查询以后验证通过，单 CWE 元数据也仍可能漏掉 NoSQL 召回。
- 应优先核实该开发测试失败的原因，并将真实查询 CWE 标签与操作/框架关系纳入索引；不能通过复制改标签或取消质量门制造命中。

## 5. 对规则生成效果的判断

本次扩大了材料可用范围，**没有重新执行端到端规则生成对照**。现有最完整效果证据仍是 [旧集复测](legacy-rag-matched-results.md)：旧 K 15/18、新 v6 auto 1/18（共同旧预算 6000）。上下文超限、重复取证和自由 QL 生成的退化，不能仅靠扩库解决。

检索 top-k 与生成上下文上限保持原值。扩库增加可选择的材料，不把新增原文整体加入每次模型输入。后续先恢复受限规格/模板生成、精简模型视图、修正取证循环，再冻结新语料做因子消融与独立泛化验证。

下一批优先把官方开发测试通过范例提高到至少 80 个，补充版本化写法指南、真实编译修正和跨框架安全反例。这些是 [计划目标](../rag-corpus-expansion-plan.md)，当前尚未完成。
