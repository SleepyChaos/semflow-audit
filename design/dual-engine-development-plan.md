# 双引擎发现改造计划

2026-10-04 制定，2026-10-05 完成首版实现。目标：CodeQL 标准套件和独立 Agent 并发分析同一不可变快照，统一复核两路候选。保留人工确认、规则发布和修复接受边界。扩展套件留到后续实验。

## 工作包

1. 项目地图：确定性收集文件、模块、Python 符号/导入线索和文档；区分词法线索与已解析调用。源码分窗、模块轮转，记录未检查和无法读取的窗口。不把读取覆盖当作安全覆盖。
2. 独立粗筛：不输入 CodeQL 告警、不依赖危险关键词。按窗口调查输入/权限/状态/危险行为，允许只读跨文件补证。候选保存安全条件、观察、未知前提与源码证据；假设保持 pending。
3. 并发编排：LangGraph 两个分支，汇合等待两路结束。各自保留成功、失败、取消和部分完成；CodeQL 失败不得变为空告警成功。已有历史任务保留旧配置。
4. 统一复核：新 review v4 分批处理静态和粗筛候选，保留原始记录与来源。支持/排除必须引用真实源码；排除还需明确反证，未决前提阻止武断结论。根因关联是建议，不删除候选、不自动提升新增召回。
5. 上下文/恢复：项目地图与完整证据保存在材料中，每批仅载入所需正文。模型调用、工具和候选受全阶段及局部预算约束；部分失败仍保存覆盖和历史，重试创建新阶段。
6. 展示：上传默认开启并发粗筛；页面显示两路状态、检查窗口/文件、未检查与根因关联建议。确认后的候选仍可进入修复/规则生成。

## 验证

普通代码/API/CLI 测试覆盖无危险关键词模块、跨文件保护、来源隔离、并发汇合、单路失败、预算耗尽、真实位置绑定与不删除候选。真实模型小案例对照另报，不把脚本替身集成当作准确率证据。GUI 验收由用户执行，不启动目标服务或加入利用重放。

效果实验：固定独立样例，比较原 CodeQL→复审与新双路→复核。记录独立新增根因、漏检、误排、未决比例、覆盖及每项真实新增发现的成本。发现确认与 QL 可生成性分别统计。
