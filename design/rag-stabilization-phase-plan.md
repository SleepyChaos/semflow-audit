# RAG 规则稳定化阶段（2026-10-04）

## 原因和目标

原冻结六类任务、每类三轮对照：旧 K 方案 15/18，新 v6 部署方案 1/18。主要失败发生在上下文装配、重复源码读取和自由 QL 生成；扩库本身不能修复这些问题。

本阶段完成定义：

1. v7 保留源码、漏洞描述、双库知识三项输入及不可变完整材料。模型视图去除重复的验证元数据，禁止截断完整查询和关键源码。重复读请求返回已读证据和明确反馈，有界停止，可恢复且不重复执行。
2. 支持的 detector 类型默认采用类型化规格及固定版本的官方模板；经真实源码与知识校验后允许有限的外部 API 返回值 source 扩展。其他目的仍走显式自由 QL 路径，标注能力边界。编译、开发正反例和原项目复跑继续强制执行，发布仍需人工审批。
3. 扩展库采用最新有效版本，区分编译通过和官方开发测试通过，正确识别多 CWE 标签，补齐 XSS 路由及 SQL/NoSQL 范例缺口。官方开发测试通过范例目标至少 80 条；未通过条目保留日志且不作为通过范例。
4. 原冻结六类任务 × 三轮进行 v7 对照，保持模型、生成预算、评估数据不变。目标至少恢复旧 K 的 15/18，并单独验证未建模 API 扩展；失败不能作为速度提升。
5. 对上下文精简、受限生成、取证进度反馈和向量检索进行组件消融；报告全请求成功率、失败阶段、成功请求耗时及 token。保留负结果，不用开发样例替代独立评估。

## 本阶段范围

聚焦规则生成与知识库质量；语义修复模块保留当前行为。本阶段不增加漏洞利用复测、服务启动测试、GUI 测试或自动发布。80 条是开发验证材料数量，不代表检测 80 种漏洞有效；六类任务仅支持小样本工程结论。

方法沿用已审阅的 [论文评述](../research/notes/rule-generation-paper-review.md)、[生成重设计](development/rule-generation-redesign-plan.md) 与本项目的 [原集对照](../benchmarks/reports/legacy-rag-matched-results.md)。本轮首先修正已观测工程失败，然后用消融检验各部分贡献。


## 执行记录与第二轮修正

首轮冻结 v7 的 108 次实验完成：old K 15/18、full v7 12/18、去精简 5/18、自由 QL 8/18、关闭进度反馈 15/18、BM25 15/18。负结果完整保留。进度反馈和向量检索没有显示稳定增益，不能筛选较好组冒充默认效果。

根据开发阶段日志修正 v8：明确 inspect 只准备规则代码流、不提前要求后续 CodeQL 知识或修复业务契约；注入实际 EOF/窗口完整性和观察到的基线；要求至少一条真实源码事实引用；保留 critical unknown 阻断和自定义来源信任依据。重试反馈保留完整候选、错误、正反例实际/预期位置，移除验证元数据及依赖安装日志；模型上下文预算按实际传输 JSON 判断。不同 source 模型绑定不同规则 ID，防止复用模板 ID 冲突。

v8 第二轮预定五组各 18 次新请求：完整、去范围提示、RAG 提前提供、BM25、自由 QL；复用首轮 18 个明确标注的旧 K 对照，不重复计入新请求。固定旧隐藏集和 6000 输出预算，不依据隐藏失败改模型/金标。另跑外部 SDK 三轮与新别名/可信 API/局部遮蔽安全反例。冻结执行中不修改核心实现。

实际产品角色路由检查另发现 16/20：Python/JavaScript命令注入通用类型槽无词法交集、JavaScript路径模块实际名为TaintedPath、Python NoSQL实际名为NoSqlInjection。通用双集合可用性40/40不能替代产品路由检查。针对三类非旧集操作的路由补丁将在冻结实验完成后接入，不改变旧六类任务/SDK角色调用；失败记录与定向复测单列。
