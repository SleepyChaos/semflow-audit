# 审计后续流程界面改进

日期：2026-10-14。分支：`codex/downstream-audit-ux`。

## 检查范围与发现

检查现有任务的修复与报告、RAG 规则两个页面，以及现有修复、验收和规则接口。现有任务有已确认漏洞，尚无实际修复补丁或生成规则。补丁结果布局使用标注为合成数据的组件样例验证，未触发真实模型调用、补丁接受或规则发布。

| 流程 | 原界面的主要问题 | 本次改进 |
| --- | --- | --- |
| 选择修复目标 | 通用安全类型标题掩盖具体漏洞，报告和高级表单占据主线 | 显示具体标题、位置、CWE；可全选；报告和高级配置默认收起 |
| 生成补丁 | 难以判断后台处于哪一步，失败原因不突出 | 四步状态轨道；真实阶段名称、提交限制、失败提示；保留历史尝试 |
| 审阅补丁 | 原始 Diff 文本埋在折叠项，阅读成本高 | 优先展示真实持久化补丁，按文件切换、并排/逐行、行号、增删计数及红绿标记 |
| 前后验证 | 检查范围和最终结论混在技术信息中 | 独立检查卡片与修复前后用例表；未运行明确展示；保留技术详情 |
| 规则生成 | 默认目的与检测规则主线不符，需理解大量可选项 | 默认漏洞检测规则、自动生成策略；选择已确认漏洞后复用目标，独立集和高级配置收起 |
| 规则验收与发布 | 编译、正反例、项目回扫等状态不易比较 | 六项验收摘要，状态颜色与文字共同呈现；不可发布时显示限制 |

## 实现边界

- 修复展示读取 `/repairs/{id}/diff`，用固定版本 `diff@8.0.4` 解析；不把模型建议的旧/新片段当成已应用补丁。
- 展示 Diff 中实际包含的修改区域与上下文，不宣称包含完整文件。读取失败、无效补丁不显示为空的成功结果。
- 步骤状态取自持久化阶段和产物。历史顺序使用关联阶段的创建时间，不按随机 UUID 判断先后。
- 保留原有隔离修复、验收、人工接受和规则发布条件；语法通过不能代表漏洞已修复。
- 代码在独立工作树，预览前端为 5180；原前端 5177 保留。预览仍代理现有 API，未建立隔离数据副本。
- 检查限于生产构建、改动文件静态检查、Diff 解析单测和浏览器关键交互；未运行完整模型审计链路。

## 2026-10-15 流程拆分

- 新增独立的“审计报告”页面，代码修复页只选择已确认漏洞、生成补丁、查看 Diff 与验证。复审页提供两个明确入口。
- CodeQL 与 AI 初审两栏日志仅保留在 AI 复审页底部，其他页面不再挂载。
- 报告材料补齐复审介绍、利用用例、有效分类、反证与缺失前提及根因关联建议；新报告使用 v3 提示词。关联证据使用原任务、原快照已有绑定，不允许跨漏洞引用。材料变更使旧报告过期。
- 5180 预览切换至该工作树的 API 8002 和独立 Redis 队列 13，参考 API 8001 与队列 12 保持原状；两边仍共享现有数据库和审计产物，方便继续查看当前任务。运行配置保存在忽略目录 `artifacts/local-ui/`。

## 后续迭代顺序

1. 项目验收测试：将测试集准备、执行、失败恢复进一步分步呈现，减少技术字段直接暴露。
2. 规则样本：将正反例的 JSON 编辑改为结构化文件和预期结果表，保留原始格式查看。
3. 报告交付：展示报告对应的复核和修复版本，突出过期状态、下载产物和应用补丁步骤。
4. 真实产物验证：有实际补丁和规则后，以真实多文件补丁、失败验收和发布限制走完整链路，再完善细节。
