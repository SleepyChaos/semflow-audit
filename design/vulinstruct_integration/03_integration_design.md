# 集成架构与实现顺序

将公开通用安全规范冻结进现有语料端口。在兼容模式下，Scout 保持原来的源码窗口、结构化输出和证据校验。增强模式对同一窗口从程序语义中检索有限条候选，在有相关匹配且上下文充足时追加安全约束。检索只读当前执行明确授权的语料快照。CodeQL 分支保持独立，未匹配、不可用和超时都有独立回执。

复审经原来的候选 bundle 接收规范引用。规范不进入可引用源码证据集合。需要检查的条件、查阅源码和候选状态由现有缺口与义务模块处理。历史复审协议保持可读。新实验可以用强确认和强排除的同一策略分别执行增强和非增强组。

1. 添加冻结策略和候选引用的接收测试。验证无 CWE、无匹配及错误降级、证据隔离。
2. 复用 `public.corpus`、`runtime.corpus_inputs`、`KnowledgeRetriever` 实现检索，以当前函数和调用上下文构造查询。
3. 从 Scout 输入契约、CLI 和平台请求连接增强开关。候选和单元回执保存真正提供过的规范。
4. 在现有独立复审和定向取证入口投影规范约束，并对没有已验证反证的新版排除保持未决。
5. 固定 A–F 的入口、预算、快照和模型，先通过替身流水线，再进行小规模真实 API 测试。真值在独立评分端读取。

默认关闭增强。词法模式使用现有 BM25 适配器及独立的相关性门槛。VulInstruct 的密集检索、本系统未接通的规范向量模式和 NVD 归纳分别记录。当前集成以 BM25 和相关性门限运行。
